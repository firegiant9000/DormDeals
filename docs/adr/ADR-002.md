# ADR-002: Move the backend to Firebase (Auth, Firestore, Storage)

**Date:** 2026-06-16 (records a change made incrementally between 2025-11 and 2026-01)
**Decision Makers:** DormDeals Team
**Status:** Accepted. **Supersedes [ADR-001](ADR-001.md).**

## 1. Context

ADR-001 chose Express.js with a relational database. During the course the
team moved authentication, data and file storage onto Firebase so the app
could ship without running or paying for a server. The Express server in
`index.js` now only serves the built `dist/` folder for the Render deployment;
`api/server.js` and `database/` were the unused remains of the original plan
(removed September 2026).

## 2. Decision

- **Firebase Authentication** for sign-in (email/password).
- **Cloud Firestore** for users, listings, cart and favorites, with access
  enforced by `firestore.rules` and tested against the emulator
  (`npm run test:rules`).
- **Firebase Storage** for listing images, governed by `storage.rules`.
- **Firebase Hosting** as the deployment target; the GitHub Actions workflow
  deploys hosting, rules and indexes on every push to `main`.
- Client-side service layer (`src/services/*`) wraps the Firebase SDK;
  components never call Firebase directly.

## 3. Consequences

- **Positive:** no server to operate; real-time updates; security is
  declarative and unit-tested; free tier covers a single campus.
- **Negative:** business rules live in the client and in rules, not in a
  server; Firestore costs scale with reads (see `docs/firestore_costs.md`);
  the legacy `api/`, `database/`, `render.yaml`, `Dockerfile` and Express
  static server were removed in September 2026 along with the Render path.
